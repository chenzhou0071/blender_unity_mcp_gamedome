# 古墓丽影风格扩展设计：「序章」垂直切片（一期）

> 日期：2026-10-11 ｜ 状态：设计定稿（brainstorming 产出，用户已逐段确认）
> 上游：现有 blender_mcp 项目（M0-M5 已完成：程序化神庙 + 主角动画 + 玩法闭环 + 音效氛围）
> 定位：**求职作品**——写实化、完整度优先；分期开发，本 spec 仅覆盖一期

## 1. 背景与目标

现有项目是一个"程序化资产 → 灰盒玩法 → 打磨"的垂直切片（神庙内约 3-5 分钟）。本设计将其扩展为**写实丛林风格的「序章」线段**：从神庙石门出发，穿越户外峡谷（草原 → 岩缝 → 藤蔓 → 河谷 → 悬崖），抵达崖顶遗迹。

| 决策项 | 结论 |
|---|---|
| 用途 | 求职作品，美观为硬指标（面试级观感） |
| 节奏 | 分期：一期最小完整循环 → 二期战斗与物品 → 三期存档与发布 |
| 时间 | 无硬期限，质量优先 |
| 美术风格 | 写实丛林（古墓丽影 2013/崛起方向，目标观感 ≈85%） |
| 素材来源 | **全程序化自研**（Blender MCP 脚本产出，不用第三方素材库） |
| 渲染路线 | **URP 增强**（复用现有工程，加装水体/雾/后处理） |
| 关卡形态 | 线性峡谷冒险（镜头感优先，非开放世界） |

## 2. 一期范围

**包含**：七段线性峡谷关卡 + 蹲行 + 挥刀（砍藤）+ 游泳 + 爬绳 + 血条 + 摔伤/死亡重生 + ESC 菜单（继续/退出）。

**不包含**：
- 二期：枪械（右键肩射）/ 近战战斗 / 背包 / F 拾取 / 解密扩展
- 三期：完整存档（ESC 保存/回档）/ 打磨 / 正式打包发布

## 3. 关卡设计（七段，约 200-300m 线性）

```
[现有神庙] → (1)石门后·出口楼梯 → (2)草原段 → (3)岩缝(蹲) → (4)藤蔓墙(砍)
                                                              ↓
        (7)崖顶遗迹(终点) ← (6)对岸悬崖(爬绳) ← (5)河谷(游泳)
```

| 段 | 内容 | 能力展示 | 视觉锚点 |
|---|---|---|---|
| 1 出口楼梯 | 石门后新增门厅 + 下行石梯 | 衔接 | 洞口透光——第一眼"惊艳镜头" |
| 2 草原段 | 开阔草坡、岩石、远山雾 | 跑动 | 太阳 + 体积雾 + 植被 |
| 3 岩缝 | 低矮狭缝必须蹲行 | C 蹲 | 狭窄光影 |
| 4 藤蔓墙 | 藤蔓封路，挥刀砍断 | 刀（左键） | 残枝掉落 |
| 5 河谷 | 河流横亘，游泳穿越 | 游泳 | 水面反射 + 水流 |
| 6 悬崖 | 南岸崖边抓绳，沿斜绳横越深渊 | 爬绳 | 深渊全黑不可达（坠入即死）+ 漂浮雾层渐没入黑暗 |
| 7 崖顶遗迹 | 火盆遗迹 + 终点触发 | 到达结算 | 二期解密入口 |

## 4. 技术架构

### 4.1 移动能力（扩展现有 ThirdPersonController）

| 能力 | 实现要点 |
|---|---|
| 蹲下（C） | 胶囊体压低 + 速度降；**头顶障碍检测禁止站起**（岩缝必蹲才能过） |
| 游泳（简版） | 入水判定 → 泳态：**固定浮在水面高度**、划水前进、岸边自动上岸；**无氧气/体力消耗** |
| 爬绳 | 绳索为场景对象：南岸崖边靠近 + 前推抓住 → 沿**斜绳横越深渊**上行 → 对岸崖顶落地；**固定绳索、不做自由荡绳**；**深渊不可达——坠入即死**（深渊带 z 194-208、y<-4 即死区） |
| 挥刀 | 左键挥刀动画 + 刀锋前方扇形判定；**一期仅对藤蔓生效**（砍断 → 残枝掉落 → 通路打开） |

### 4.2 世界构建

- **地形**：Blender 脚本生成峡谷地形网格（高度场 + 岩壁断面）→ 导入 Unity；草原/河谷/深渊（不可达坠亡区）在同一张约 200-300m 的线性地形内。
- **素材库**（Blender 程序化，分批迭代）：岩石×4 变体 / 大树×3 / 灌木 / 草簇贴图卡 / 藤蔓×2 / 绳索 / 遗迹石构件 / 楼梯石阶；统一 **PBR 材质**（石/土/苔藓/树皮/树叶，程序化节点烘焙贴图）。
- **植被散布**：Unity 脚本按规则散布（坡度/高度/随机），**instancing + 密度预算**守性能。
- **水体**：**Unity 6 URP 水体系统**做河流 + 泳区判定；若不适用则退化为自定义水面 Shader（保底）。
- **氛围**：体积雾/大气 + 太阳光/天空 + 后处理链扩展（现有 Bloom/ACES 基础上加厚）。

### 4.3 HUD 与系统

- **血条**：左上角；伤害源 = **摔落**（按落差高度掉血）+ **深渊即死**（坠入 y<-4 立即死亡，不等落地）。
- **死亡/重生（简版）**：血=0 或坠入深渊 → 只狼风黑幕（朱红楷体大字“失足迷途／归火重启”）→ 回到最近**检查点火盆**。
- **ESC 菜单**：继续（生效）/ 退出（生效）/ **保存·回档（灰置占位）**。
- **性能守护**：目标打包后 60fps；每个大节点做**真实打包冒烟**（吸取"编辑器正常、打包翻车"的静态批处理教训）。

### 4.4 检查点火盆（两期分级设计）

- **一期（自动记录，不写盘）**：走近火盆 → 自动记录为**复活点**（运行时内存）；火盆常燃，兼作沿路光源与视觉路标；触发时屏幕角落提示"检查点已记录"。
- **三期升级（真存档）**：靠近火盆按 **F 互动** → 火盆**"未燃 → 燃烧"点燃特写**（镜头推近）→ 写盘存档。
  **视觉语言：全场唯一燃烧的火盆 = 当前存档点**（其余熄灭）——一眼可辨存档位置。
  **三期前置改造（待办）**：点燃特写希望**直接复用现有火焰造型本身**——`add_flame` 的 5 瓣外焰 + 3 瓣内芯尖火苗，与碗口发光炭火圆柱（材质槽 `M_Fire` / `M_Fire_Core`）**"从未燃一起生长到完整形态"**。现状是火焰与石盆同属一个合并网格（`SM_Brazier`），无法单独做动画；三期需将其**拆分为独立对象**（如 `SM_Brazier_Fire`）或做坍缩→生长的形态动画（blendShape）。Unity 端点燃时以 **scale 0→1 生长 + 自发光/点光渐入 + 音效** 呈现；"未燃"状态即火焰部分缩至最小/隐藏，石盆本体始终无火。一期保持现状不动。
- **依据**：现有火盆资产 + 火光语言直接复用；"篝火=存档"是游戏通用直觉，零学习成本。

## 5. 里程碑分解（M6-1 ~ M6-8）

| 里程碑 | 内容 | 排序理由 |
|---|---|---|
| M6-1 地形骨架与第一眼 | 峡谷地形（Blender）+ 门厅出口楼梯 + 草原段 + 太阳/雾/天空/后处理 + 岩石/草/树首版 | 最早看到"好看"，立信心 |
| M6-2 蹲行 + 岩缝段 | C 蹲、头顶检测、岩缝地形打通 | 系统最简单 |
| M6-3 挥刀 + 藤蔓段 | 主角挥刀动画（Blender 补）+ 刀模型 + 藤蔓可破坏 | 依赖动画资产 |
| M6-4 游泳 + 河谷段 | URP 水体/泳态/上岸 | 依赖地形挖河 |
| M6-5 爬绳 + 悬崖段 | 绳索对象/攀爬状态/跨崖 | 移动系统里最难 |
| M6-6 崖顶遗迹 + 终点 | 遗迹构件 + 火盆光/火语言复用 + 到达结算 | 收束线路 |
| M6-7 HUD 与菜单 | 血条/摔伤/死亡重生(检查火盆)/ESC 菜单 | 系统齐备后接入 |
| M6-8 打磨与一期验收 | 植被密度/性能/镜头走查/打包冒烟/全流程验收 | 交付闸门 |

**节奏约定**：每段"做 → 自测 → 用户试玩验收 → 提交"；素材每段 2-3 轮精修迭代。

## 6. 验收标准

- **每里程碑**：功能可用 + 用户试玩验收 + 涉及资产时截图对比。
- **一期总验收**：全流程 5-10 分钟走通（支持重复游玩）；关键镜头观感达标；打包版 60fps；Console 0 Error / 0 Warning；**真实打包冒烟测试**。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 程序化写实素材质量不稳定 | 每类资产 2-3 轮精修迭代 + 统一材质/光照/雾兜底整体感 |
| URP 水体系统适配不确定 | 保底退化为自定义水面 Shader（流动+法线动画） |
| 植被/雾的性能开销 | 密度预算 + instancing + LOD 计划 + 每节点打包实测 |
| 编辑器与打包行为差异 | 所有关键变更走真实打包冒烟（历史教训：静态批处理误标） |

## 8. 二期/三期轨道（接口预留，本 spec 不细化）

- **M7 战斗与物品**：枪（右键进入肩射视角）/ 刀对敌升级 / 背包 / F 拾取 / 解密扩展。
- **M8 存档与发布**：完整存档（ESC 保存/回到存档点/退出）+ 火盆火焰改造（从 `SM_Brazier` 拆分为独立对象，支持"未燃→点燃一起生长"动画，见 4.4 三期前置改造）+ F 点燃特写升级 + 打磨 + 正式打包发布。

## 9. 技术栈基线

- Unity **6000.3.21f1**（URP）——现有工程与代码/资产全量复用；
- Blender（经 MCP 桥接）程序化管线——沿用 `blender_assets/scripts` 既有模式；
- 现有系统复用：ThirdPersonController / ClimbSystem / AudioManager / PostFxSetup / URP 后处理链。
